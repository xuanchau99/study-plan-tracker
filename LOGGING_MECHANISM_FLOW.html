Sơ Đồ Cơ Chế Rolling Log

Giải thích cơ chế cắt file Log theo Ngày (Daily) và theo Dung Lượng (Max Size) cấu hình trong file logback-spring.xml.

Đang chờ hệ thống phát sinh Log...
1

Application Logging

Controller -> Service -> Repository -> SLF4J -> Logback
Phát sinh Log Đa Tầng

Tất cả các tầng Controller (tiếp nhận API), Service (chứa Business Logic), và Repository (truy vấn DB/Hibernate) đều sử dụng log.info, log.error của SLF4J để đẩy luồng dữ liệu tập trung vào Appender.

2026-09-11 20:20:01 INFO - User created 2026-09-11 20:20:05 WARN - High CPU ... (hàng triệu dòng log)
2

Cắt File (Rolling Policy)

SizeAndTimeBasedRollingPolicy
Tách theo Ngày + Size 10MB

Hệ thống tự động theo dõi. Nếu sang ngày mới, hoặc file log hiện tại đạt đến ngưỡng 10MB, nó sẽ tạo file mới với hậu tố %i.

10MB quiz-system-2026-09-11.0.log (10MB) quiz-system-2026-09-11.1.log (10MB) quiz-system-2026-09-11.2.log (Đang ghi)
3

Dọn Dẹp Rác Tự Động

maxHistory & totalSizeCap
Tránh tràn ổ cứng (Disk Full)

Chỉ lưu trữ các file log của 30 ngày gần nhất. Hoặc nếu tổng dung lượng tất cả các file log vượt quá 1GB thì sẽ tự xóa file cũ nhất.

30 1GB // Tự động xóa log của tháng trước

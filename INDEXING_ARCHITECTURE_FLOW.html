Sơ Đồ Đa Kiến Trúc Indexing

Mô phỏng 3 kỹ thuật lập chỉ mục (Indexing) đang được ứng dụng trong dự án: B-Tree truyền thống, In-Memory Index siêu tốc, và NoSQL JSONB Index.

Chờ lệnh giả lập tìm kiếm và cập nhật dữ liệu...
1

B-Tree Index (PostgreSQL)

@Table(indexes = { @Index(...) })
Tìm kiếm User, Quiz -> O(log n)

Sử dụng JPA Indexing để tạo B-Tree trên các cột thường xuyên tìm kiếm (ví dụ: username, title). Giúp tra cứu hàng triệu bản ghi không bị Full Table Scan.

@Index(name="idx_username", columnList="username", unique=true) // Tránh trùng lặp username // Tăng tốc findByUsername
2

In-Memory Index (Redis Hash)

redisTemplate.opsForHash()
Tracking High-Throughput -> O(1)

Dữ liệu cập nhật liên tục (như Heartbeat Task) không đánh index ở DB mà dùng key `taskId` tra cứu thẳng trên RAM. Sau đó mới Sync ngầm xuống DB.

HINCRBY daily_task_progress {taskId} 1 // Redis Hash là một In-Memory Index // Tốc độ phản hồi: ~1ms
3

Bán Cấu Trúc (JSONB)

@JdbcTypeCode(SqlTypes.JSON)
Dữ liệu động (Details, Evidence)

Thay vì tạo chục bảng phụ và đánh vô số Index Khóa ngoại (Join), ta lưu nguyên cục JSON. PostgreSQL dùng GIN Index hỗ trợ query trực tiếp vào Object JSONB.

@Column(columnDefinition="jsonb") private QuestionDetails details; // Gộp chung cấu trúc câu hỏi // Không cần JOIN nhiều bảng

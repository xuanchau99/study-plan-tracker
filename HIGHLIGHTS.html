Ghi Log Request/Response Chi Tiết Nhất & Cuốn Vòng Theo Ngày

Spring Boot Logging RollingFileAppender ContentCachingWrapper

Hệ thống tự động bắt và lưu toàn bộ API requests ra file giống hệt thư mục storage/logs của Laravel. Đặc biệt, nó được cấu hình cơ chế Rolling Policy: Tự động tách file mới mỗi ngày hoặc khi vượt quá 10MB, tự động xóa file cũ sau 30 ngày để chống tràn ổ cứng Server.

Cách Triển Khai (Implementation)

Sử dụng logback-spring.xml thay vì application.yml để cấu hình xoay vòng file log. Đồng thời, tự viết một ApiLoggingFilter bọc bởi ContentCachingRequestWrapper và ContentCachingResponseWrapper để có thể đọc được chính xác 100% Payload gửi lên và Dữ liệu JSON Server trả về (Response) mà không làm hỏng stream của Request.

Công Cụ "Dội Bom" Load Tester Tích Hợp

Vanilla JavaScript Promise.allSettled

Không cần dùng phần mềm bên thứ 3 như JMeter, chúng ta đã tích hợp sẵn một trang Web Load Tester với UI xịn xò để kiểm tra sức chịu đựng của Server bằng cách bắn hàng trăm request nộp bài cùng lúc.

Cách Triển Khai (Implementation)

Tạo một file load_tester.html đặt trực tiếp trong thư mục public của React để tránh lỗi CORS. Sử dụng JavaScript vòng lặp for kết hợp với Promise.allSettled() để kích hoạt đồng loạt hàng trăm hàm fetch() không đồng bộ, tạo ra lượng tải khủng khiếp lên máy chủ trong cùng 1 mili-giây.

Phân Trang Client-side Siêu Tốc

React Hooks Array Slicing

Bảng dữ liệu ở màn hình Quản trị (Admin) sẽ không bao giờ bị tràn lề dù có hàng ngàn bản ghi, nhờ hệ thống phân trang cực nhanh, không có độ trễ chuyển trang.

Cách Triển Khai (Implementation)

Thay vì bắt Backend phải đếm và chia trang bằng lệnh SQL LIMIT/OFFSET nặng nề, ta fetch toàn bộ dữ liệu 1 lần. Ở Frontend, dùng hàm .slice((page-1)*10, page*10) của Array để cắt mảng theo State currentPage. Việc này tận dụng sức mạnh CPU của trình duyệt Client, giảm hoàn toàn gánh nặng cho máy chủ RDBMS.

Chấm Điểm Bất Đồng Bộ (Async Worker)

RabbitMQ Message Queue

Tính năng đắt giá nhất hệ thống. Giúp Server sống sót khi hàng ngàn sinh viên nộp bài thi cùng lúc khi tiếng chuông hết giờ vang lên.

Cách Triển Khai (Implementation)

Khi User gọi API Submit, Server không chấm điểm ngay. Nó gói thông tin thành một JSON Message, ném vào RabbitTemplate rồi lập tức trả về HTTP 202 cho User. Ở phía sau, một hàm đánh dấu @RabbitListener sẽ thong thả lấy từng Message ra chấm điểm. Cơ chế này gọi là "Fire and Forget" kết hợp "Queue Buffering".

Thông Báo Thời Gian Thực Kèm Trạng Thái

WebSockets (STOMP) React State

Chuông thông báo ở thanh điều hướng sẽ tự động nảy số màu đỏ mỗi khi có bài thi được chấm xong, mà không cần người dùng phải bấm F5 tải lại trang web.

Cách Triển Khai (Implementation)

Mở kết nối SimpMessagingTemplate song công (full-duplex). Khi RabbitMQ chấm bài xong, nó Push data qua Socket Channel. Trên Frontend, Component chuông báo duy trì một mảng trạng thái (Array State) cho các thông báo. Khi click vào nút Mark all read, React sẽ map qua mảng và đổi trạng thái Unread thành Read siêu mượt.

Lưu Tạm Bài Làm Bằng RAM (Redis)

Redis Hash Spring Data Redis

Mỗi khi học sinh tích chọn một đáp án A, B, C, D, đáp án được lưu tự động lên Server để lỡ có rớt mạng thì bài thi không bị mất, tốc độ lưu chỉ tính bằng micro-giây.

Cách Triển Khai (Implementation)

Sử dụng cơ chế Write-Behind Cache. Ghi đáp án vào Redis Hash (được lưu trên RAM nên tốc độ đọc/ghi là O(1)). Không hề đụng chạm tới Database PostgreSQL cho đến khi người dùng bấm nút Nộp Bài chính thức. Triệt tiêu hoàn toàn sự nghẽn cổ chai (Disk I/O Bottleneck).

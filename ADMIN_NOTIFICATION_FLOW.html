Sơ Đồ Cơ Chế Chống Quá Tải Thông Báo

Khi 10,000 học sinh nộp bài cùng một lúc (Traffic Spike), nếu Server đẩy 10,000 thông báo WebSocket lập tức về trình duyệt của Admin, trình duyệt sẽ bị treo (Freeze/Crash).
Giải pháp: RabbitMQ đóng vai trò làm "Hồ chứa" (Buffer) kìm hãm luồng dữ liệu, cho phép Background Worker chấm điểm và nhả thông báo nhỏ giọt đều đặn, đảm bảo trang Dashboard của Admin luôn mượt mà.

Hệ thống đang hoạt động bình thường...
1

RabbitMQ Queue

Hàng đợi Message Broker
Tồn đọng: 1000 Events

Hứng trọn 1000 lượt nộp bài cùng lúc. Đóng vai trò là cái Phễu (Buffer).

2

Background Worker

ExamProcessorService.java
processExamSubmission()

Rút từng bài ra chấm, sau đó dùng vòng lặp For để gửi kết quả cho các Admin.

// Lặp qua danh sách Admin và gửi for (User admin : admins) { notificationService .sendNotification(admin, msg); }
3

STOMP Server

NotificationService.java
convertAndSendToUser(...)

Đẩy Frame JSON qua giao thức STOMP TCP tới trình duyệt của Admin.

messagingTemplate .convertAndSendToUser( admin.getUsername(), "/queue/notifications", dto );
4

Admin Dashboard

AdminDashboard.jsx (React)
client.subscribe('/user/queue/notifications')

Lắng nghe và hiện Toast thông báo "nhỏ giọt" đều đặn. Giao diện vẫn mượt mà.
